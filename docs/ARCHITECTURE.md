# 实现架构

## 一个引擎，两个运行端

`core/` 使用 C++17，不依赖 ESP-IDF、浏览器、网络、堆分配或时间系统调用。Engine 只接受来自适配层的音频时间戳，以微秒表示；浏览器 C ABI 接受毫秒并做有界转换。网页不另写一套 JavaScript 判定器，直接调用相同核心编译的 WASM。

状态流：`Menu → CountIn → Listen → Ready → Repeat → Result → 下一关/重试`。十二关完成或生命耗尽进入 GameOver。随机谱面由 seed、关卡和难度确定；同关重试不重新抽题。

三档难度都使用同样判定窗口，不靠缩小窗口制造难度，而逐步增加音色、节拍密度、休止、和弦与小节长度。该生成器是首版内容方案，不代表已进行玩家留存或教育效果验证。

## 判定与结算

原始击打时刻减去用户配置的输入偏移，再找 ±150 ms 内、同键且尚未判定的最近音符。Perfect/Good/Bad 分别为 1000/700/300 分，多按扣 100 分，最低为零。命中不可重复计数。有效输入可以先于复现首拍，只要在允许的 early window 内；示范期间按键不计分。

精度为加权得分占最大得分的千分比，过关阈值 Easy 60%、Normal 70%、Hard 80%。漏拍打断连击。最终 Miss 在末尾结算，以便主循环先排空已经捕获、但尚未交付的事件。额外 30 ms 是交付缓冲，不扩大判定窗口；正输入偏移另外纳入最后结算时刻。

只有通过的回合计入 session score；失败重试不能反复刷分。固件最高分仅 RAM；浏览器另用 localStorage 保留本机最高分。浏览器暴露本地调试 API，不作为防作弊客户端。

## 八种鼓音与混音

`Synth` 用程序生成底鼓、军鼓、闭镲、拍手、低/高通鼓、开镲、吊镲，另有节拍器与成功/失败提示。所有音色与正弦表由本项目代码生成，没有录音、外部歌曲或提示音资源。最多 12 个软件声部，声部满时替换最老者；固定包络、限幅与音量控制避免无限响声和整数溢出。

固件实时按 32 kHz 生成 PCM 并写 I2S，鼓音和节拍器可以叠加。网页用同一 Synth 预渲染短 AudioBuffer，再由 Web Audio 混音调度；它不是 ESP32-S3 的性能/时延仿真。

## ESP32-S3 任务与时间轴

音频任务 core1 / priority12，输入扫描 core0 / priority10，主任务独占游戏状态。1 ms 输入扫描使用独立 5 ms 按下、3 ms 释放消抖。消抖事件保留候选边沿时刻，而不是晚几毫秒的通知时间。编码器采用 Gray-code 四相状态机，非法两位跳变清空部分移动。

I2S `on_sent` 累计 DMA 呈现帧数，并记下 ESP 单调时钟锚点；捕获的输入时刻映射到该音频帧时间轴。DMA 边界中断、DAC/功放和声学路径的偏移仍须真机测量，微秒变量不意味着微秒级物理精度。

计划队列长度 1，按 epoch 整体替换；实时时间戳输入队列长度 128，实时鼓音队列长度 64。主循环先读输入再推进结算时刻。输入扫描停顿 >20 ms、输入溢出或交付延迟 >100 ms 会使挑战失效；音频排队溢出、欠载或谱面声音晚 >30 ms 进入锁定静音，LED 通道错误同样停止游戏，需重新上电检查。异常不隐藏成“玩家漏拍”。

GPIO8 由唯一硬件适配层管理，正常游戏不重复上/下电。实时路径不写 Flash；不进行网络收发、麦克风采集或睡眠唤醒。

## Web Audio 调度

音符通过 AudioContext 时间轴提前排队，不依赖动画帧触发声音；采用约 150 ms 调度展望和 20 ms 调度轮询。输入通过 `getOutputTimestamp()` 将 DOM 的 performance 时间映射到输出音频时间；不可用时用 latency 属性估计并允许手动校准。动画只显示状态，不决定采样时钟。严重迟到、失焦、后台或音频暂停时取消本次挑战。

## 首版边界

不包含旋钮谱面、多人对战、完整歌曲、MIDI、无线控制器、麦克风评分、OTA、持久化固件分数或竞技反作弊。要加入这些能力，应先完成现有板上闭环的编译、音频输出、输入丢失检测和真实延迟验收。
