# 第一次上板

## 开始前

ESP-IDF 5.5.5 的实际目标构建已经通过，构建日志和生成包可在仓库 Actions 查看；**尚未进行本项目真实设备烧录或实板验收**。先按 [FLASHING.md](FLASHING.md) 下载并校验可信固件包，保留脚本默认的完整备份。修改源码则先按 [BUILD.md](BUILD.md) 构建和打包。

确认板型为 EasyInput V2.0 / AI Keyboard V2.1，阅读 [HARDWARE.md](HARDWARE.md)。首次采用有人看护的 USB 台架与低音量，不依赖电池运行。准备原固件的完整备份及其同名 JSON，保存到私密位置。

## 写入与启动

开发板开机时短按并松开一次 BOOT；不按住 BOOT 配合上电。关闭所有串口占用程序，确认实际端口，然后使用防护脚本，不手填三个镜像的写入地址：

```bash
python scripts/be.py flash --port YOUR_CONFIRMED_PORT
```

写入和回读校验成功后关机，再正常开机。重新列端口，查看应用日志：

```bash
python scripts/be.py ports
python scripts/be.py monitor --port YOUR_NEW_PORT
```

正常启动应打印 `Beat Echo 0.1.0` 和共享电源等待的未实测提示。菜单没有连续背景音乐，按 S1 试听，不应仅因开机安静判定扬声器故障。

## 验证顺序

先观察低音量菜单状态，串口应打印版本、BPM、难度及共享 rail 稳定等待的未资格确认提示。检查 GPIO8 上电过程与下游信号：禁止带电修改引脚或用 MCU 输入替代物理测量。

在菜单逐一按 S1–S8：每键一个不同鼓音，长按只有一次；快速重复和多键和弦都要测试。调整旋钮 BPM，方向反转只修改 `CONFIG_BE_ENCODER_REVERSE`，不要交换电气引脚。菜单长按旋钮至少 800 ms 松开应切换难度。

开始挑战，检查四个阶段的节拍器、八键复现及第五灯判定。先验证 Easy / 90 BPM，再试 Hard / 160 BPM 和高密度和弦。反复返回菜单和重试，不能有上一轮残留声音或输入。

记录输入任务扫描停顿、队列溢出、音频欠载及 LED 超时；这些错误必须可见并取消不可信回合。确认调高亮度、音量后仍无异常电压下降、设备复位、失真或过热。没有实测前不要提高限制。

## 延迟与判定

建议用逻辑分析仪/示波器同时观察实际按键边沿和音频输出时间。当前微秒时间戳和固定 DMA 配置只提供可校准的结构，不提供已经测得的端到端延迟值。

先确定固定偏移，再确认多次测量的波动。`CONFIG_BE_INPUT_OFFSET_MS` 为正表示从输入时刻减去偏移；不要只凭一个主观感觉同时修改多个时钟或直接删除消抖。

## 故障与恢复

看到 Audio/LED fault、状态灯快速闪烁或锁定静音，先停止并检查日志，重新上电后再诊断。不在错误状态继续认为成绩有效。若固件无法启动，按前述 BOOT 操作进入下载模式，在再次确认设备后恢复原固件。

交付验收至少分别保存：工具链版本和构建日志、实际烧录日志、正常启动日志、真实输入与音频测量、共享电源波形、长时间运行记录。不得仅用一张浏览器截图勾选硬件验收。
